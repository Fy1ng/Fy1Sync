# Fy1Sync 六平台独立验收

## 本地运行

在待验收 SHA 的独立检出中准备锁文件依赖、FFmpeg 和 `npm run fixtures` 生成的测试视频, 再运行 `npm run build`。自动验收由 `e2e/electron.ts` 为每个用例创建并清理 `e2e/.data` 下的资料。测试结果可用 `STREAM_SYNC_E2E_OUTPUT_DIR` 指向 `.runtime-cache/p07-e2e`。

```powershell
$env:STREAM_SYNC_E2E_OUTPUT_DIR = '.runtime-cache/p07-e2e'
npm run test:e2e -- e2e/platform-acceptance
```

离线场景覆盖播放器、切房、账号切换、未知态、增强 PiP 及无活动归因的同文。媒体是合成源, 弹幕由现有主进程夹具注入。PiP 场景额外把本地媒体登记到真实 IPC 的播放源, 让分窗独立取到合成媒体。对接入 `setDouyuLotteryFixture` 的集成构建设置 `STREAM_SYNC_P07_INTEGRATED=1`, 额外验收斗鱼同文可展开、媒体暂停时按平台时钟结束及切房清理。匿名取流可显式运行 `public-live.spec.ts`。设置 `STREAM_SYNC_P07_PUBLIC_LIVE=1` 和下列所需公开在播 URL, 不导入浏览器凭据。

| 平台 | 环境变量 |
| --- | --- |
| 斗鱼 | `STREAM_SYNC_DOUYU_LIVE_URL` |
| 哔哩哔哩 | `STREAM_SYNC_BILIBILI_LIVE_URL` |
| 抖音 | `STREAM_SYNC_DOUYIN_LIVE_URL` |
| 虎牙 | `STREAM_SYNC_HUYA_LIVE_URL` |
| YouTube | `STREAM_SYNC_YOUTUBE_LIVE_URL` |
| Twitch | `STREAM_SYNC_TWITCH_LIVE_URL` |

同平台双房增加 `STREAM_SYNC_P07_DOUYU_SECOND_URL`, 由操作者确认两条 URL 对应不同正式房号。跨平台双路使用斗鱼和 Twitch。匿名结果只计入取流与播放器验收。

## 人工对照

1. 固定 `P00-candidate.txt` 的完整 SHA。使用新建的测试应用资料和独立浏览器配置, 仅操作者正常登录。为账号记脱敏代号。选择正在直播的正式房间或视频场次, 检查该账号的权限、活动期限、任务剩余额度、当日重置时区和读数精度。记录只读入口、指标原名及单位。
2. 关闭其他设备与标签页对该账号的播放, 包括嵌入播放器。先读取静止基线。用官方端正常看一段足以越过指标显示粒度的时间。停止播放, 从不会自动播放的官方账号或任务视图重复读到稳定, 记录播放区间、查询时间和结算所需时间。若官方对照无可比较读数, 写明权限、隐私设置、封顶或入口不可用等原因。
3. 待官方端对照结算后再取 Fy1Sync 时段的独立起点。只在 Fy1Sync 从 `画面片源` 或 `解说片源` 载入同一正式房间并正常观看, 记实际播放起止及缓冲、暂停、中断区间。停止播放后, 用同一个只读入口按官方对照的结算窗口读取后值。若仍待结算, 记录后续读数和时间。查询若会自动播放, 明确记录污染, 改用只读页面或将该轮标记无法归因。
4. 同房主窗加 PiP 使用单一实际播放时段, 记录主窗和 PiP 的重叠区间并与单窗对照。检查两窗同一时段没有重复入账。两个不同房间先各取独立基线, 载入主源和解说源, 切换被选中的房间, 分别复读两个房间。跨平台双路也逐路记录各自账号、房间、指标和单位。切换账号后为新账号重取基线并观察旧值清理。
5. 对暂停、缓冲/重连、回放/轮播分别记录边界, 按步骤 2 和 3 复读。待结算与确认无增量分别标注。跨重置、切房、换号、单位变更、读数回退、待结算和封顶的区间单独记录。同账号同房的增量验收使用身份、单位和结算条件可比较的区间。

同一账号、正式房间及指标的可归因正差可以确认该指标。今日和累计分别确认。任务百分比、任务分钟或奖励进度只确认该任务。房间热度、主播已播、历史条目、心跳回执和本地计时保留为独立证据。缺值写 `未知` 和原因, 数字 `0` 只用于确知为零的场景。

| 平台 | 分开记录的读数与归因条件 |
| --- | --- |
| 斗鱼 | 设置 > 房间数据 > 概况查看 `官方今日观看` 和 `粉丝牌累计观看`。今日要求同一平台自然日, 当前账号持有本房牌才验收累计。2026-11-06 隔离历史反例中今日 `483 -> 789 -> 1123 秒`, 两轮累计均 `4810476 秒`, 第二轮另有 7 次心跳响应。历史结果仅确认当时的今日变化。 |
| 哔哩哔哩 | 记录可归属的账号个人/任务读数与权限。`WATCHED_CHANGE` 单列作直播间统计, 天选福袋和 SC 单列作互动。 |
| 抖音 | 电商活动任务按账号、任务及活动读回, 普通福袋倒计时按活动服务端时间验收。任务达成、福袋弹幕或普通直播观看分别交付结论。 |
| 虎牙 | `看过` 单列个人历史或观看标记。只有明确的账号本房累计度量能确认累计时长。上电视、礼物和房间统计另列。 |
| YouTube | 历史条目按账号和场次回看并验证历史可用。频道 Analytics 按房间或频道统计处理, 记录频道权限。 |
| Twitch | 频道积分和 Drops 分两行, 分别记录频道、账户权限、活动资格和结算窗。秒数或加分以对应界面的实际单位保存。 |

## 收消息和权限

- 从真实用户入口载入两路及打开聊天, 核对房间归属、普通文字、原生表情和资源失败的文本回退。缺 UID、昵称装饰、礼物价格或时间字段时, 检查未知态, 保留仍可显示的文字。SC、礼物到账回执、任务完成、粉丝牌更新分开记。记录平台适配实际支持的能力和原因。
- 用主进程入口夹具放入活动, 记录正式房号、活动 ID、有效期及官方时钟。重复推送同活动, 检查只提示一次。依次发送可确认来源的活动口令、手打同文、来源不明同文、错房同文、到期后同文和开奖公告。仅可证实绑定同房同活动且到达时有效的活动口令允许按设置折叠。手打同文、来源不明同文和开奖公告可见或可复看。平台无法提供可靠来源时保留消息, 记录区分能力未知。
- 设置媒体延迟并再次推送。活动卡以官方时间更新。检查在有效期内到达但延迟后才显示的消息, 以及跨过截止后才到达的消息。切到第二个正式房间, 检查旧活动、旧房消息及排队提醒清理, 回房时同活动提醒遵循去重规则。
- 真实账号仅查看写入口的权限和预览, 不实际发送或领取。提交、回执、失败或重登分支只使用合成夹具。活动或平台读回缺失时记录是否有明确的不可用提示。

| 平台 | 从产品入口验证的预期与夹具 |
| --- | --- |
| 斗鱼 | 通过解说弹幕选房进入主播抽奖与设置房间数据。抽奖原行可展开、平台时钟过期后撤下活动, 活动来源无法区分时标为疑似。用 `setDouyuLotteryFixture` 和现有弹幕钩子。 |
| 哔哩哔哩 | 载入或选择正式弹幕房间, 打开聊天与房间数据。访客或上游 -101 读表情目录时核对登录提示, 目录权限保持只读。注入 `bilibiliReplay` 观察原生表情回退、礼物、SC 撤下和房间数据; 合成 WATCHED_CHANGE 为 1024 时个人项仍未知。`bilibiliLotteryReplayFixture` 轮换 771、772 和空活动, 核对同文可展开与不同轮次清理。 |
| 抖音 | 选择合成抖音聊天房间, 访客发送禁用且提供登录入口。注入 `douyinLotteryFixture` 检查普通福袋和主播场次, 更换场次或重连后旧快照和提醒清理。手打及来源不明的同文可复看; 使用 `douyin-send.spec.ts` 验证既有普通文字的合成回执和风控。 |
| 虎牙 | 连接正式虎牙聊天房间, 检查只读聊天、上电视倒计时及房间数据个人未知态。使用 `huyaOnTvWire` 的有效、过期、失败及当房数据, 对照 `6298` 活动通知与普通 `1400` 同文和错主播信号。两个窗口观察同房时只发一次提醒。 |
| YouTube | 通过已解析视频进入聊天与房间数据, 核对缺 Data API 凭据的用户可见状态, 不把播放登录当作聊天授权。现有 `youtubeChat` 夹具覆盖只读授权和换场; 重新选择同频道另一个视频时清理旧消息。个人历史、单视频分钟和 Analytics 分开展示。 |
| Twitch | 通过已解析频道进入聊天与房间数据, 核对缺授权或读 scope 的状态, 聊天发送保持不可用。用 `twitchEventSub` 合成授权与重连, 验证共享聊天原房、投递房和撤回。积分、连看、Drops 和领取权益各自未知。 |

## 证据条目

每个指标或互动场景各填一条。清理账号名、UID、头像、凭据、URL 中的授权参数和其他个人数据。证据类型填 `当前版本人工实测`、`匿名网络烟测`、`离线合成` 或 `历史实测`。

```text
候选完整 SHA / 证据类型:
平台 / 客户端版本与权限 / 脱敏账号:
正式房间、视频场次或活动 ID:
场景 / 界面入口或证据出处:
指标类别 / 官方指标原名 / 单位:
前值 / 前值查询时间含时区:
后值及延迟复查值 / 各查询时间含时区:
实际播放开始与结束含时区 / 暂停缓冲时段 / 播放端:
任务上限、重置时间、结算窗口 / 对照组证据编号:
结论 (通过、失败、不支持、待真实样本) / 复现条件与归属编号:
```
